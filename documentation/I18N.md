# Internationalization (i18n) Guide

This document explains how internationalization works in the VaultScope Storefront.

## Overview

VaultScope supports **German** and **English** with:

- ✅ Context-based translation system
- ✅ URL-based locale detection (`/de/` prefix)
- ✅ Namespace organization
- ✅ Type-safe translations
- ✅ Language switcher component
- ✅ SEO-friendly routing

## Supported Languages

- **English (en)**: Default language
- **German (de)**: German translations with `/de/` URL prefix

## Usage

### In Components

```typescript
import { useTranslation } from '../i18n/useTranslation';

function MyComponent() {
  const t = useTranslation('common');
  
  return (
    <div>
      <h1>{t('welcome')}</h1>
      <button>{t('getStarted')}</button>
    </div>
  );
}
```

### Nested Keys

Access nested keys with dot notation:

```typescript
const t = useTranslation('home');

<h1>{t('hero.title')}</h1>
<p>{t('hero.subtitle')}</p>
```

### Multiple Namespaces

```typescript
const tCommon = useTranslation('common');
const tNav = useTranslation('nav');

<button>{tCommon('getStarted')}</button>
<nav>
  <a href="/">{tNav('home')}</a>
  <a href="/about">{tNav('about')}</a>
</nav>
```

### Dynamic Keys

```typescript
const status = 'active';
const t = useTranslation('dashboard');

// Construct key dynamically
<span>{t(`status.${status}`)}</span>

// With fallback
<span>{t(`status.${status}`, `Unknown status: ${status}`)}</span>
```

## Locale Detection

### URL-Based Routing

German URLs have `/de/` prefix:

```
/              → English homepage
/de/           → German homepage

/pricing       → English pricing
/de/pricing    → German pricing

/infrastructure/cloud → English cloud page
/de/infrastructure/cloud → German cloud page
```

### Implementation

```typescript
// App.tsx
export function App() {
  const locale = window.location.pathname.startsWith('/de') ? 'de' : 'en';

  return (
    <LocaleProvider locale={locale}>
      <Routes>
        {/* English routes */}
        <Route path="/" element={<Home />} />
        <Route path="/pricing" element={<Pricing />} />
        
        {/* German routes */}
        <Route path="/de" element={<Home />} />
        <Route path="/de/pricing" element={<Pricing />} />
      </Routes>
    </LocaleProvider>
  );
}
```

## Language Switcher

### Using LocaleLink

The `LocaleLink` component automatically prefixes URLs:

```typescript
import { LocaleLink } from '../i18n/LocaleLink';

// Automatically adds /de/ prefix when locale is 'de'
<LocaleLink to="/pricing">Pricing</LocaleLink>

// When locale is 'en': <a href="/pricing">
// When locale is 'de': <a href="/de/pricing">
```

### Language Switcher Component

```typescript
function LanguageSwitcher() {
  const { locale, setLocale } = useLocale();

  const toggleLocale = () => {
    const newLocale = locale === 'en' ? 'de' : 'en';
    setLocale(newLocale);
    
    // Update URL
    const path = window.location.pathname;
    if (newLocale === 'de' && !path.startsWith('/de')) {
      navigate(`/de${path}`);
    } else if (newLocale === 'en' && path.startsWith('/de')) {
      navigate(path.substring(3));
    }
  };

  return (
    <button onClick={toggleLocale}>
      {locale === 'en' ? '🇩🇪 Deutsch' : '🇬🇧 English'}
    </button>
  );
}
```

## SEO Considerations

### Language Meta Tags

```typescript
import { Helmet } from 'react-helmet-async';
import { useLocale } from '../i18n/context';

function MyPage() {
  const { locale } = useLocale();

  return (
    <>
      <Helmet>
        <html lang={locale} />
        <meta property="og:locale" content={locale === 'de' ? 'de_DE' : 'en_US'} />
      </Helmet>
      {/* Page content */}
    </>
  );
}
```

### Alternate Links

For better SEO, add alternate language links:

```typescript
<Helmet>
  <link rel="alternate" hreflang="en" href="https://vaultscope.de/pricing" />
  <link rel="alternate" hreflang="de" href="https://vaultscope.de/de/pricing" />
  <link rel="alternate" hreflang="x-default" href="https://vaultscope.de/pricing" />
</Helmet>
```

## Best Practices

### 1. Use Descriptive Keys

```typescript
// ✅ Good - Clear, descriptive keys
{
  hero: {
    title: 'Infrastructure You Can Trust',
    subtitle: 'Deploy servers in seconds',
    cta: 'Get Started Now',
  }
}

// ❌ Bad - Generic, unclear keys
{
  text1: 'Infrastructure You Can Trust',
  text2: 'Deploy servers in seconds',
  button1: 'Get Started Now',
}
```

### 2. Group Related Strings

```typescript
// ✅ Good - Grouped by feature
{
  pricing: {
    monthly: 'Monthly',
    annually: 'Annually',
    save: 'Save {{percent}}%',
  }
}

// ❌ Bad - Flat structure
{
  pricingMonthly: 'Monthly',
  pricingAnnually: 'Annually',
  pricingSave: 'Save {{percent}}%',
}
```

### 3. Keep Translations Consistent

Use the same terminology across the app:

```typescript
// ✅ Good - Consistent terminology
{
  common: {
    service: 'Service',
    services: 'Services',
  },
  dashboard: {
    myServices: 'My Services',
    createService: 'Create Service',
  }
}

// ❌ Bad - Inconsistent terminology
{
  common: {
    service: 'Service',
  },
  dashboard: {
    myServers: 'My Servers', // Should be "Services"
    addInstance: 'Add Instance', // Should be "Create Service"
  }
}
```

### 4. Handle Pluralization

For languages with complex pluralization, consider libraries like i18next. For simple cases:

```typescript
function formatCount(count: number, t: any) {
  return count === 1 
    ? t('service') 
    : t('services');
}

<span>{count} {formatCount(count, t)}</span>
```

### 5. Extract All User-Facing Strings

Never hardcode user-facing strings:

```typescript
// ✅ Good
<button>{t('submit')}</button>

// ❌ Bad
<button>Submit</button>
```

## Variables in Translations

### Simple Interpolation

```typescript
// Translation file
{
  welcome: 'Welcome, {{name}}!',
}

// Component (implementation needed)
<span>{t('welcome', { name: user.name })}</span>
```

Current implementation is simple. For complex interpolation, consider:

```typescript
function interpolate(template: string, vars: Record<string, string>) {
  return template.replace(/\{\{(\w+)\}\}/g, (_, key) => vars[key] || '');
}

const t = (key: string, vars?: Record<string, string>) => {
  const text = translations[key];
  return vars ? interpolate(text, vars) : text;
};
```

### Test Missing Translations

```typescript
function findMissingKeys(en: any, de: any, path = '') {
  const missing: string[] = [];
  
  for (const key in en) {
    if (!(key in de)) {
      missing.push(`${path}${key}`);
    } else if (typeof en[key] === 'object') {
      missing.push(...findMissingKeys(en[key], de[key], `${path}${key}.`));
    }
  }
  
  return missing;
}

test('No missing German translations', () => {
  const missing = findMissingKeys(en, de);
  expect(missing).toEqual([]);
});
```

## Common Pitfalls

### 1. Forgetting to Add German Translation

Always add both English and German:

```bash
# Check for missing translations
git diff src/i18n/locales/en/
git diff src/i18n/locales/de/

# Ensure both changed
```

### 2. Hardcoded Strings

Use grep to find hardcoded strings:

```bash
# Find potential hardcoded strings
grep -r ">" src/ | grep -v ".test." | grep -v "import" | grep "{'"
```

### 3. Wrong Namespace

```typescript
// ❌ Wrong namespace
const t = useTranslation('common');
<h1>{t('hero.title')}</h1> // 'hero' is in 'home' namespace

// ✅ Correct namespace
const t = useTranslation('home');
<h1>{t('hero.title')}</h1>
```
